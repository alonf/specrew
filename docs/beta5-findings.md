# Beta5 findings

- **B5F-001 — Task-record ownership is not explicit (deferred; 2026-09-14, build 8d3f9906):** the implementer owns the plan table's Status, Agent, Actual and Verdict, which terminal-state validation reads; the task-progress writer owns the ledger and updates state but never writes the plan table, so a coordinator told “writers own the records” searched for a nonexistent invocation and stalled T310 sign-off (row subsequently repaired in router commit `14181a0`); implement refocus already says to update the row but omits this ownership distinction—either synchronize the row through the writer or state the implementer's ownership explicitly in one canonical implementation instruction. Evidence: [writer](../scripts/internal/task-progress.ps1), [validator](../extensions/specrew-speckit/scripts/validate-governance.ps1), [implement refocus](../extensions/specrew-speckit/refocus/implement.md), [resume skill](../extensions/specrew-speckit/squad-templates/skills/iteration-resume.md). Record only; beta4 unchanged.

- **B5F-002 — A mandatory stop cannot ride as a discussion default (deferred; 2026-09-14, build 8d3f9906):** beyond the accepted walk path, the clarify packet offered “Design-analysis stop… Default: skip… approve with the defaults”, stretching a clarify verdict into skipping a mandatory stop; the gate refused correctly. Coordinator rule for beta5: no lifecycle skip may be bundled into a discussion-prompt default. Record only.
- **B5F-003 — Plan artifacts preceded the design-analysis stop (deferred; 2026-09-14, build 8d3f9906):** beyond the accepted walk path, the crew wrote and committed the plan and five design artifacts in walk commit `17462e4` before the design-analysis stop, with the plan declaring that stop skipped; the order was inverted and the record false until rewritten. Preserve the mandatory stop before authoring the dependent plan artifacts. Record only.
- **B5F-004 — Stop blocks outside beta4.1 Tier 1 are unaudited against the substance-only rule (deferred; 2026-10-13, feature 202 ui-ux lens):** the maintainer's governing UX principle for 202 says a stop is justified only when the system needs a human decision AND the human lacks the context for it, and that the hook never blocks a reply over formatting. Feature 202 applies this only to the Tier 1 findings (B4F-104/106/096/107/100/102/108/105/089/101). Every other Stop-block or force-continue reason has not been checked against it. Example observed this session: the material-work turn-end declaration force-continues a stop that carries no human decision. Audit each remaining reason: keep the ones that protect authority or a needed decision, and drop or convert the formatting ones. Evidence: specs/202-beta4-1-ux-stabilization/workshop/ui-ux.md. Record only; not in 202.
- **B5F-005 — Governed script refusals can name the wrong cause when a path does not resolve (deferred; 2026-10-13, feature 202 code-implementation lens):** under the 202 principle, the system diagnoses its own failures. When confirm-workshop-lens.ps1 ran with `-ProjectRoot .` from a stale process working directory, it said the feature had "no recorded workshop plan yet" and told the agent to confirm the agenda first. In fact the agenda was confirmed, and the plan file simply was not found at the resolved path. A refusal like that sends the agent, or the human, to repeat work that is already done. Refusals should state what was looked for and where (the resolved path) before concluding that something is absent. Evidence: specs/202-beta4-1-ux-stabilization/workshop/intake-drift-log.md DRIFT-202-INTAKE-008. Record only; not in 202.
- **B5F-006 — Init's Squad output prints mojibake on a default Windows console (deferred; 2026-10-23, `specrew init` during the 202 iteration 003 Copilot re-walk setup):** `squad init`'s check marks and dashes print as `Γ£ô` and `ΓÇö`, because the console decodes Squad's UTF-8 output with code page 437. Either set the output encoding to UTF-8 for the child process, or capture its output and re-emit it decoded. Record only.
- **B5F-007 — The bootstrap summary buries the result and repeats contradicting advice (deferred; 2026-10-23, `specrew init` during the 202 iteration 003 Copilot re-walk setup):** the summary lists about 350 file lines plus Squad's own output, including `Run copilot --agent squad`, which contradicts Specrew's own launch advice. Collapse it to one line per step, with counts and the path of a full log, and do not pass through launch advice from Squad. Record only.
- **B5F-008 — The post-bootstrap guidance is stale (deferred; 2026-10-23, `specrew init` during the 202 iteration 003 Copilot re-walk setup):** `scripts/init/post-bootstrap-output.ps1` points to `docs/getting-started.md`, which does not exist in the project. - **B5F-009 — Init writes user-level hook files for hosts it reports disabled, without saying so (deferred; 2026-10-23, `specrew init` during the 202 iteration 003 Copilot re-walk setup):** init rewrote `~\.cursor\hooks.json` and `~\.codex\hooks.json` although it reported those hosts as disabled, and did not say it wrote outside the project. - **B5F-010 — Init sets `core.autocrlf=true` with a reason that undersells it (deferred; 2026-10-23, `specrew init` during the 202 iteration 003 Copilot re-walk setup):** the message calls the effect "harmless warnings". - **B5F-011 — A waiting workshop turn can end without saying what to type (deferred; 2026-10-23, the 202 iteration 003 Copilot re-walk):** after the product-domain record, the turn closed on "Next comes the short workshop agenda", which reads as if the crew is still working, and the way to close the lens ("type move on") sat in the middle of a paragraph. The stop check classes the turn as workshop-intermediate, blocks nothing, and never checks for a next action. Every turn that waits on the human should end with one line naming what to type, and the stop check should look for that line on workshop turns. Record only.
- **B5F-012 — The review-coverage stop blocks retro and closeout turns over records, identical runtime copies and test data (deferred; 2026-10-25, the 202 iteration 003 retro):** with the review allowance spent, the stop hook blocked every turn end during the retro and the closeout, although only records, runtime copies identical to the reviewed sources and test fixtures had changed, and the maintainer's partial review signoff already covered them. It counted them as "13 source files" and offered implementation decisions (`hold implementation here`, `continue without coverage until the review phase`) during a retro. Claude Code shows each block as "Stop hook error", which reads as a crash, and the text is addressed to the crew, not to the user; once it arrived garbled ("moved beyond tverage is now falling behind"). It should not block outside implementation, nor for records and test data, and anything it shows should tell the user what to type. Maintainer's report.
